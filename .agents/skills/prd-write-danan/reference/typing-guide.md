# PRD 四分法判断指南

## 快速判断流程

```
开始
  ↓
只是入口导航/纯展示？
  ├── 是 → 极简
  ↓ 否
有计算逻辑但无状态流转？
  ├── 是 → 适中
  ↓ 否
复杂业务 + 后台逻辑不存在？
  ├── 是 → 详细 - 新建
  ↓ 否
复杂业务 + 后台逻辑已存在？
  └── 是 → 详细 - 改造
```

## 四分法详解

### 1. 极简（1-2 页）

**判断标准**：纯展示/导航，无业务逻辑

**写作方式**：说清楚有哪些模块、入口、跳到哪

**典型示例**：
- 首页：导航入口集合
- 个人中心：功能入口列表
- 设置页：配置项列表

**模板结构**：
- 需求背景（精简）
- 页面模块（入口列表）
- 边界场景（简要）

---

### 2. 适中（3-5 页）

**判断标准**：有计算逻辑，无状态流转

**写作方式**：字段表格 + 计算逻辑 + 边界情况

**典型示例**：
- 排行榜：有计算逻辑和排序规则
- 运动数据：有统计数据和筛选维度
- 数据看板：有指标计算和展示

**模板结构**：
- 需求背景
- 全局筛选（如有）
- 页面模块（字段表格 + 计算逻辑）
- 边界场景

---

### 3. 详细 - 新建（5 页+）

**判断标准**：复杂业务，后台逻辑不存在

**写作方式**：先写全局业务 PRD，再写页面 PRD

**典型示例**：
- 订单系统：从零搭建的订单管理
- 支付系统：全新支付流程
- 消息中心：新的消息推送体系

**模板结构**：
1. 第一步：全局业务 PRD
   - 业务流程图（泳道图）
   - 状态流转图
   - 状态定义
   - 字段定义
   - 全局规则

2. 第二步：具体页面 PRD
   - 订单列表 PRD
   - 订单详情 PRD
   - 创建订单 PRD
   - ...

---

### 4. 详细 - 改造（5 页+）

**判断标准**：复杂业务，后台逻辑已存在

**写作方式**：直接写页面 PRD，详细说明与后台交互

**典型示例**：
- 校园活动改造：后台逻辑已存在，新增功能
- 排行榜优化：在现有基础上增加功能
- 权限升级：已有系统的权限调整

**模板结构**：
- 需求背景
- 小程序端（详细，含子页面/弹窗）
- 后台调整（详细说明调整内容）
- 权限控制（汇总）
- 边界场景与异常处理

---

## 判断技巧

### 问自己这些问题

1. **这个页面有没有业务逻辑？**
   - 只是展示/跳转 → 极简
   - 有计算/统计 → 适中或详细

2. **有没有状态流转？**
   - 没有状态变化 → 极简或适中
   - 有状态流转（如订单状态） → 详细

3. **后台逻辑存在吗？**
   - 完全新的业务 → 详细 - 新建
   - 在现有基础上改 → 详细 - 改造

4. **复杂度如何？**
   - 简单展示 → 极简
   - 中等复杂度（有计算） → 适中
   - 高复杂度（多角色、多流程） → 详细

---

## 常见误判

| 误判 | 正确判断 | 原因 |
|------|---------|------|
| 首页写了 5 页 | 极简（1-2 页） | 首页是导航入口，不需要复杂逻辑 |
| 活动管理写了 2 页 | 详细 - 改造（5 页+） | 活动管理有状态流转、权限控制，复杂度中等 |
| 排行榜写了 10 页 | 适中（3-5 页） | 排行榜有计算逻辑但无状态流转 |
