# PRD 写作流程

## 四步流程

### 步骤 1：梳理结构

**所有 PRD 都必须先梳理结构**，梳理内容：

| 梳理项 | 说明 |
|--------|------|
| PRD 范围 | 本次写哪些 PRD（小程序端、后台、H5...） |
| 页面结构 | 有哪些页面、模块、功能入口 |
| 关键逻辑 | 状态定义、权限规则、计算逻辑、特殊规则 |
| 模糊点 | 需要澄清的边界情况 |

### 步骤 2：列出确认清单

**确认清单格式**：
```markdown
确认清单：
1. 本次需求总共有哪些 PRD：xxx
2. PRD 类型判断：极简/适中/详细 - 新建/详细 - 改造
3. 页面结构：
   - 页面 1：模块 A、模块 B
   - 页面 2：模块 C、模块 D
4. 关键逻辑：
   - 状态：xxx
   - 权限：xxx
   - 计算规则：xxx
5. 模糊点：
   - 问题 1：xxx？
   - 问题 2：xxx？

等待用户确认...
```

### 步骤 3：等待用户确认

**必须等待用户确认后再执行**，确认内容包括：
- 结构是否正确
- 模块是否完整
- 关键逻辑是否准确
- 模糊点是否澄清

### 步骤 4：执行写作

#### 4.1 有原型图时的写作流程

**阶段 1：整体规划（写之前）**
- 问：准备拆成几个 PRD？哪些内容写到一个 PRD 上？
- 确定拆分方案

**阶段 2：单个 PRD 执行（每个 PRD 重复）**
1. 重新检查原型图
2. 思考是否需要调整，和用户讨论修改建议
3. 确定后执行写 PRD

**阶段 3：循环执行**
- 第一个 PRD 完成后，重复阶段 2 执行第二个 PRD
- 每个 PRD 都独立走"检查→讨论→确认→撰写"流程

#### 4.2 无原型图时的处理流程

1. **明确需求来源** - 问清楚需求背景（谁提的、解决什么问题、为什么现在做）
2. **用"5 个问题"框架澄清** - 用户问题、业务价值、核心功能、衡量标准、不做代价
3. **画简易原型确认** - ASCII 或线框图，和用户确认理解正确
4. **写 PRD 草稿，快速评审** - 只写核心，标记"待确认"
5. **迭代完善** - 根据反馈调整

**关键原则**：先确认再写，边写边确认，不猜测。
