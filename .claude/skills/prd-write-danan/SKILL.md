# PRD 写作专家（结构化版本）

## 核心理念 ⭐ 置顶

### 1.1 结构优先

**所有 PRD 都必须先梳理结构，确认后再写详细内容。**

- 结构对了，后续改动少
- 结构错了，写再多也白写
- 先梳理结构，列出确认清单，等待用户确认

### 1.2 四步流程

1. **梳理结构** → 列出 PRD 范围、页面结构、关键逻辑
2. **列出确认清单** → 明确类型、模块、模糊点
3. **等待用户确认** → 确认结构无误后再执行
4. **执行写作** → 按确认的模板写详细内容

### 1.3 四分法

| 类型 | 判断标准 | 厚度 | 写作方式 |
|------|---------|------|---------|
| **极简** | 纯展示/导航，无业务逻辑 | 1-2 页 | 说清楚有哪些模块、入口、跳到哪 |
| **适中** | 有计算逻辑，无状态流转 | 3-5 页 | 字段表格 + 计算逻辑 + 边界情况 |
| **详细 - 新建** | 复杂业务，后台逻辑不存在 | 5 页 + | 先写全局业务 PRD，再写页面 PRD |
| **详细 - 改造** | 复杂业务，后台逻辑已存在 | 5 页 + | 直接写页面 PRD，详细说明与后台交互 |

## 与 requirements-analysis 的协作流程

**前置依赖**：PRD 撰写必须基于需求分析文档（`prd/需求分析/*.md`），不接受口头需求。

```
用户需求 → requirements-analysis → prd-write-danan
           (需求分析文档)        (PRD 文档)
           prd/需求分析/          prd/
```

**触发场景**：
- 用户提供需求分析文档后说"根据这个写 PRD"
- 用户要求在需求分析完成后撰写 PRD

**禁止操作**：
1. 不可以在没有完全理解需求分析结果时直接写 PRD
2. 不接受口头需求：必须基于需求分析文档（.md 文件）
3. 不接受靠猜的需求：所有需求细节必须有文档依据
4. 未在文档中明确的内容必须标注"待确认"并询问用户

## 执行流程

按 `reference/workflow.md` 和 `reference/typing-guide.md` 执行：

### 步骤 1：判断 PRD 类型

按 `reference/typing-guide.md` 中的决策树判断类型。

**典型示例**：
| 需求 | 类型 | 原因 |
|------|------|------|
| 首页 | 极简 | 导航入口，无业务逻辑 |
| 排行榜 | 适中 | 有计算逻辑和排序规则 |
| 运动数据 | 适中 | 有统计数据和筛选维度 |
| 校园活动 | 详细 - 改造 | 复杂业务，后台逻辑已存在 |
| 订单系统 | 详细 - 新建 | 复杂业务，后台逻辑不存在 |

### 步骤 2：梳理结构并列出确认清单

按 `reference/workflow.md` 梳理结构并输出确认清单，包含：
- PRD 范围、类型判断
- 页面结构、关键逻辑
- 模糊点澄清

**必须等待用户确认后再执行**。

### 步骤 3：执行写作

#### 4.1 加载对应模板

根据类型加载对应模板：
- 极简 → `reference/templates/minimal.md`
- 适中 → `reference/templates/moderate.md`
- 详细 - 新建 → `reference/templates/detailed-new.md`
- 详细 - 改造 → `reference/templates/detailed-modify.md`

#### 4.2 字段说明规范

参考 `reference/field-specs.md`：
- **展示字段 4 要素**：计算公式、取值规则、格式、边界情况
- **编辑字段 5 要素**：字段类型、必填、输入限制、校验规则、错误提示

#### 4.3 功能详述结构

参考 `reference/function-detail-template.md`，包含用户故事、前置条件、核心逻辑、边界条件、验收标准、测试用例（MECE，每条≤20 字）。

#### 4.4 Mermaid 流程图

所有业务流程必须使用 Mermaid 语法绘制，尤其是条件分支。

## 输出规范

1. **禁止模糊表述**：不得出现"可能"、"大概"、"优化体验"等词
2. **数据流向闭环**：每个操作有明确的输入和输出
3. **Mermaid 强制性**：涉及条件分支必须用 Mermaid 流程图
4. **测试用例 MECE**：覆盖正向路径、反向路径、边界条件，不遗漏不重复
5. **新建文件输出**：保存到 `prd/` 目录下，不得覆盖原文件
