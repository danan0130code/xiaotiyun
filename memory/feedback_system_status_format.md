# system-status.md 格式要求

**最后更新：** 2026-04-28

---

## 规则

`system-status.md` 必须直接包含每个终端的完整菜单结构表，格式为：

```
| 模块 | 页面/功能 | 核心功能 |
```

每个页面用 1-2 句话说明列表做什么、有哪些操作。

## 禁止

**禁止**使用"概要 + 跳转链接"格式，例如：
> ❌ "XX系统支持A/B/C功能，详情见 XXX.md"

主文件必须自包含。

## 为什么

用户在 review 时明确要求：后续做需求时能直接看 system-status.md 就知道每个后台有哪些菜单、子菜单、列表能做什么，不需要跳转多个文件。

## 延伸阅读

详细的规则说明（如长跑计算规则、成绩计算逻辑等）可放在 `reference/` 目录的详情文件里，但主文件必须覆盖所有菜单和页面。
